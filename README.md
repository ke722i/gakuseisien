# gakuseisien

## このリポジトリについて

学生支援系のLaravelアプリを開発するためのリポジトリです。基本の考え方や、どこに何を書くかの詳細は [docs/laravel-guide.md](docs/laravel-guide.md) にまとめています。

## GitHub運用ルール（簡易版）

このREADMEでは、次の3つの書き方を統一する。

1. VS Codeでのコミット
2. GitHubでのPR作成
3. PM/SVのコミット

### 共通ルール

- 日付は `yy/MM/dd` 形式（例: `26/06/16`）
- 変更内容は英語で記載
- 説明では日本語で変更内容を記載

## 1. VS Codeコミット

形式: `yy/MM/dd 英語で変更内容を記載（google翻訳などで記載してくれて構いません。最悪日本語でも構いません。）`

例: `26/06/16 adjust text form`

`テキストフォームを適用しました。`

## 2. PRタイトル・説明

### PRタイトル

`yy/MM/dd 英語で変更内容を記載（google翻訳などで記載してくれて構いません。最悪日本語でも構いません。）`

例: `26/06/16 adjust text form`

### PR説明（本文）

以下を必ず書く。

1. 変更内容（日本語で簡素に記載する）

テンプレート

```
変更内容: テキストフォームを適用しました
```

## 3. PM/SVコミット

形式: `yy/MM/dd 承認者名`

詳細には、実施内容・確認結果・対象を記載する。

例: `26/06/16 Mise`

`動作確認済み feature01`

## 起動手順（ローカル開発）

### 1. 最初に 1 回だけやること

```bash
composer install
npm install --ignore-scripts
```

```bash
copy .env.example .env
php artisan key:generate
```

`.env` には各自の PostgreSQL 情報を入れてください。

- `DB_CONNECTION=pgsql`
- `DB_HOST=127.0.0.1`
- `DB_PORT=5433`
- `DB_DATABASE=gakuseisien`（必要に応じて変更）
- `DB_USERNAME=postgres`（各自のユーザー名に変更）
- `DB_PASSWORD=`（各自のパスワードを設定）

```bash
php artisan migrate
```

### 2. 毎回の起動方法

まずはリポジトリ直下の `start-dev.cmd` を実行してください。これが通常の起動入口です。

- VS Code から起動する場合: ワークスペースを開くと自動で `start-dev.cmd` 相当の処理が動きます。
- VS Code 以外から起動する場合: エクスプローラーやターミナルから `start-dev.cmd` を実行します。

`start-dev.cmd` は次をまとめて行います。

1. Laravel サーバーを起動する
2. Laravel の `http://127.0.0.1:8000` と Vite の `http://127.0.0.1:5173` が両方応答するまで待つ
3. ブラウザを自動で開く

### 3. 手動で直接起動したい場合

```bash
composer run dev
```

そのあとブラウザで `http://127.0.0.1:8000` を開いてください。

もし見た目が崩れる場合は、`start-dev.cmd` を使って起動してください。Laravel だけ先に開くのではなく、Vite の準備が終わってからページを表示するためです。

### 4. 補足

- Windows では `pcntl` が使えないため、既定の起動スクリプトから `php artisan pail` は外しています。
- `.env` は `.gitignore` 済みのため、DBパスワードは `.env` にのみ記載してください。
- `.env.example` にはパスワードを記載しないでください（空欄のまま運用）。

# Git ブランチ運用ルール

このプロジェクトのブランチ運用ルールです。
**作業を始める前に必ず一読してください。**

---

## ブランチ構成

| ブランチ | 役割 |
| --- | --- |
| `main` | 本番用。直接コミットしない。 |
| `develop` | 開発の中心。各自の作業はここから分岐し、ここに合流させる。 |
| `feature/名前` | 各自の作業ブランチ。`develop` から作る。 |

> ⚠️ `feature/` はあくまで名前の付け方（命名ルール）です。
> Git に「develop の下の階層」という親子構造はなく、すべて並列のブランチです。

---

## いちばん大事なルール

> **develop が更新されたら、ブランチを作り直さず、
> 自分の feature ブランチに develop の内容を取り込む。**

ブランチを毎回作り直す必要はありません。
ずっと同じ feature ブランチを使い続けながら、
必要なときに develop の最新を取り込みます。

---

## 1. develop の内容を自分のブランチに取り込む

自分が作業している間に `develop` に新しい変更が入った場合、
その内容を自分のブランチに取り込みます。
**ブランチは作り直しません。今のブランチのまま取り込みます。**

### コマンドの場合

```bash
git switch feature/自分の名前
git merge origin/develop    # develop の最新を自分のブランチに合流させる
```

### VSCode の場合

1. 左下のブランチ名が**自分のブランチ**になっていることを確認
2. `Ctrl + Shift + P` を押す
3. `merge` と入力し「**Git: ブランチをマージ...**」を選ぶ
4. 一覧から `origin/develop` を選ぶ

> 💡 イメージ：`develop`（みんなの最新原稿）の追加分を、
> 自分の作業（コピー原稿）に取り込む作業です。
> 自分の作業内容は消えずにそのまま残ります。

---

## 2. 作業内容を保存・共有するとき（push）

### コマンドの場合

```bash
git add .
git commit -m "変更内容のメモ"
git push origin feature/自分の名前
```

### VSCode の場合

1. ソース管理パネル（`Ctrl + Shift + G`）を開く
2. 変更ファイルの **＋** ボタンでステージング
3. メッセージを入力してコミット
4. 同期ボタン（🔄）で push

---

## コンフリクト（衝突）が起きたら

`develop` で変更された箇所と、自分が変更した箇所が
**同じファイルの同じ行**だと、コンフリクトが発生します。

VSCode なら衝突箇所が色分け表示され、
「現在の変更を採用 / 入ってくる変更を採用」をクリックで選べます。
どちらを残すか判断して解決し、再度コミットしてください。

判断に迷ったら、勝手に解決せずチームに相談すること。

---

## やってはいけないこと

- `main` ブランチへ直接コミット・push しない
- 他人の `feature` ブランチへ `--force`（強制）push しない

---

## 困ったときのチェックリスト

| 症状 | 確認すること |
| --- | --- |
| 自分のブランチに develop の最新が入っていない | 手順1のマージを実行したか |
| マージしても変わらない | 自分の feature ブランチにいる状態で実行したか |
| push できない | 自分のブランチにいるか、コミット済みか |
